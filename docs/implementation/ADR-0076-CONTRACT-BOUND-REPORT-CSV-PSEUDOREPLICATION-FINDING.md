## Accepted amendment, 2026-08-22: withdraw prose evidence and establish the code/CSV lane

Alex permanently withdrew prose as a sc-referee evidence channel system-wide. This amendment applies
that controlling rule to the dependence lane: the dependence check must not consume report text,
Markdown, comments, docstrings, prose admissions, prose N witnesses,
prose suppressors, selected-path mentions, or report result literals. Free-text wording cannot create,
suppress, corroborate, or select a Finding. Code structure, frozen data structure, the existing human
contract record, and statically resolved established API names are the only permitted inputs.

The sealed report/CSV envelope failed its frozen acceptance bar: 0/3 positives were recognized, 0/3
negatives were convicted, there were zero Findings, replay was identical 6/6, and all 31 closure
components matched. The custodian burned the envelope and prohibited reuse of its case bytes as future
blind positives
(`evaluation/development/blind-envelope-2026-08-21/CUSTODY_LOG.md:76-77`;
`evaluation/development/blind-envelope-2026-08-21/AUDIT_RESULTS.json:1-15`). The opened cases and labels
are retained only as development evidence.

This amendment has the following controlling effects:

1. Sections 1 through 3 below continue to govern unchanged: profile `1.1.0`, the existing Answer and
   verified-assertion authority chain, the authority-bound CSV path/digest, unit column, group column,
   and controller preflight/final verification all stand.
2. The complete CSV parser, multiplicity facts, D1' candidate/within-unit-index/composite-key rule, and
   their finite bounds stand. They may be reused without report evidence.
3. The report half of section 4, the report-derived fact in section 5, every `reported_text` admission,
   N witness, path anchor, result lexer, and prose suppressor, and the report-specific validation clauses
   are withdrawn from Finding eligibility. They remain retained implementation and burned-history bytes
   and must not be extended or used to qualify a pin.
4. The active report adapter is demoted to retained, question-only history. It cannot supply the
   dependence binding's observed operand, cannot be named by a new qualification, and cannot be promoted
   by the burned envelope. Its existing CSV-side code may be called only as deterministic structured-data
   machinery by the replacement adapter.
5. The replacement representation is one `static_source` code/CSV adapter governed by
   `PSEUDOREP-CODE-SLICE-DESIGN-2026-08-22.md`. It preserves the same check ID, candidate, contract
   authority, first three semantic roles, generic detector, controller preflight, and one dependence pin
   slot. The fourth role is renamed from historical `selected_result_sink` to
   `result_output_sink`: output reachability does not establish selection, primacy, reporting, reliance,
   or a scientific claim. The lane receives a new check/adapter/grammar identity and requires a wholly
   fresh sealed envelope before any Finding promotion.
6. The bounded Finding remains a contract-versus-observed-analysis conflict, not an accusation that the
   science is invalid. Its evidence subject changes from selected report wording to exact checked
   analysis-code dataflow; no report phrase is quoted or interpreted.
7. Finding eligibility requires both test-argument slices to terminate at one accepted reader whose
   static path byte-equals the authority path. A second accepted reader anywhere in scope, an alternate
   `.ipynb`/`.R` analysis surface, a registered-statistics import in another Python file, an unregistered
   reader-component call reaching output, or an unresolved construct causes abstention. Root
   `analysis.py` is a naming-convention admission gate, never evidence that the file or result is primary.
8. Interprocedural inlining is deferred from the first code-adapter version. This is a decision, not an
   open builder option; all four K cases remain 0/4 coverage cases and contain other unsupported
   selection/transform constructs even under hypothetical bounded inlining.
9. Envelope 2 freezes and digests the exact prompt-author briefing bytes as well as every prompt. Its
   only code/platform constraint is one root `analysis.py` in Python. It contains three positives and
   five negatives, including a per-unit summary loaded from a second CSV and an off-registry
   dependence-aware primary with an illustrative raw test; acceptance is 3/3 positives and 0/all
   negatives.

Where the original Decision, Consequences, Validation, or Alternatives text below conflicts with this
amendment, this amendment controls. The original text is retained verbatim as the audit trail of the
accepted route that was built, frozen, measured, and reversed. No production pin was installed from that
route, so this amendment withdraws an unpromoted eligibility proposal rather than revoking a shipped
dependence Finding capability. The same permanent no-prose rule governs other check lanes; migrating
their existing implementations is outside ADR-0076's dependence-specific decision surface and is not
optional evidence-policy discretion.

The opened burned cases are development evidence only. Under the final reviewed loop grammar, P1's
pre-test and P3's post-test descriptive loops are admitted because they only read tracked values, bind
names absent from test-argument slices, and send closed mean/std/len reductions exclusively to print.
The honest code-lane expectation is therefore 3/3 opened positives and 0/3 opened negatives, with N3's
first source-ordered refusal being the group-column mutation at line 29.

## Decision

### 1. Extend the existing requirement profile; do not add an authority type or CLI flag

Keep profile ID `scientific_check_requirement_v1` and bump its current-creation schema version from
`1.0.0` to `1.1.0`. A `1.1.0` profile contains exactly the existing four fields plus
`semantic_role_authority`.

For
`check:authorized-independent-unit-entry-into-row-independent-procedure` and candidate
`one-analyzed-row-per-authorized-independent-unit`, `semantic_role_authority` contains exactly:

```json
{
  "authorized_independent_unit_key": {
    "material_input_path": "NORMALIZED/RELATIVE.csv",
    "column_name": "EXACT_HEADER",
    "group_contrast_column": "EXACT_GROUP_HEADER"
  }
}
```

The path is one normalized repository-relative POSIX `.csv` path under the companion design's safe
ASCII segment grammar. Both columns match the companion design's closed safe ASCII header grammar,
differ byte-exactly, and are compared byte-exactly after CSV decoding. The group/contrast column is
human authority and is not inferred from a header, report, or table labels. No aliases, inferred values,
extra roles, or project-prose values are accepted. Other checks under `1.1.0` require
`semantic_role_authority: {}`.

Version `1.0.0` locks remain replayable under their old meaning. They contain no unit-key authority and
cannot satisfy this new Finding predicate.

### 2. Bind the authority to exact CSV bytes inside the method contract

When creating a dependence `1.1.0` contract, `method-contract` must require the named CSV to exist as
one regular file and force it into the snapshot's material full-digest set. The profile manifest gains
`authority_binding_snapshot`, containing exactly the authorized path, unit column, group/contrast
column, and controller-observed content digest.

The human Answer's `answer_value` contains the selected dependence operand and the exact
`semantic_role_authority`. The human declaration and verified derivation copy it in
`x-semantic-role-authority`; the verified derivation also carries
`x-authority-binding-snapshot`. The existing Answer, semantic assertion, ScientificContract, profile
manifest, and semantic lock remain the authority chain. No new record type is created.

The public record schema remains v0.19.0. Its Answer permits an unconstrained structured
`answer_value` and `x-` extensions
(`src/sc_referee/resources/schemas-v0.19.0/schemas/v0.19.0/answer.schema.json:95-167`). The
profile-version bump and this ADR carry the semantic versioning; accepted public schemas are not edited.

### 3. Make verified existing authority available before inspection, then verify it again

The controller must preflight a supplied dependence `1.1.0` lock before scientific-adapter evaluation:
verify the parent lock, one human Answer, verified assertion, Answer digest, unchanged governing task,
and current material path/full digest. It freezes those existing Answer/assertion records in
`FrozenInspectionContext.shared_derivations`. This is an internal immutable view, not public authority.

The adapter may consume only that exact verified pair. After the adapter produces one question, the
existing `bind_frozen_method_contract` path repeats the complete verification and creates the current
