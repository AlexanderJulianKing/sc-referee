You are authoring one complete, self-contained small analysis project. Write it into the current working directory. The project has exactly four files at the top level: a raw data file named data.csv, a second small CSV whose name makes plain that it holds the adjusted p-values delivered by the upstream analysis stage, a Python analysis script named analysis.py, and a short report named report.md. SCENARIO

A high altitude medicine study on acclimatisation prophylaxis, run as one site of a multi-centre expedition programme. Sixty-four trekkers are the subjects, all ascending the same route on the same schedule. Thirty-two took acetazolamide 125 mg twice daily from the day before ascent, and thirty-two took a matching placebo. All measurements below were taken on the second morning at the 4300 m camp, and every trekker was measured. The four outcome variables below were declared in the programme protocol, in this order, before the expedition.

Declared outcome family, in this fixed order:
1. Peripheral oxygen saturation on room air, as a percentage. The acetazolamide group averages roughly 88.5 and the placebo group roughly 85.9, with person-to-person spread of about 3.0.
2. Lake Louise acute mountain sickness score, 0 to 12 points. Roughly 2.1 and 3.6, spread about 1.8.
3. Resting heart rate, in beats per minute. Roughly 82 and 88, spread about 9.
4. Nocturnal periodic breathing, as apnoea and hypopnoea events per hour of sleep. Roughly 12 and 26, spread about 10.

In this programme the statistical testing of the declared family is not done at the site. The programme's central analysis stage pools and tests the family and returns the per-outcome adjusted p-values to each site as a small results file. Your project therefore receives those adjusted values as data.

DATA FILES

data.csv holds one row per trekker and nothing else: no repeated rows, no summary rows, no blank cells. The columns, in this order, are a trekker identifier, the allocation group, then one column per declared outcome in the declared family order. Column naming scheme: every column name is lower case with underscores; the identifier column is a short scenario-specific prefix followed by a zero-padded number; the group column is named for the allocated drug and holds exactly two short text labels, one for each allocation; each outcome column name states the measured quantity and ends with its unit abbreviation, except the symptom score, whose name states the quantity and its scale. Every trekker has a value for every outcome.

The second CSV holds one row per declared outcome, in the declared family order, with the outcome name exactly as it appears as a column name in data.csv, the raw p-value and the adjusted p-value produced by the central stage, and a short text field naming the correction that stage applied to the family of four. Its values must be plausible for the data in data.csv, with the two outcomes that separate most clearly staying significant after adjustment.

Invent realistic values consistent with the typical values and spreads given above, rounded the way an expedition medicine team would record them. Keep the realistic mixed picture those numbers imply: two or three outcomes clearly separated between the groups and the rest only slightly separated. Both CSVs are fixed data files. analysis.py must read them and must never generate, simulate, or overwrite either one.

ANALYSIS

analysis.py is a single Python script at the project root. On the raw file it does descriptive work and routine data checks only: it reports the group sizes, the per-group summary values and spreads for each declared outcome, the group difference for each outcome, and simple checks that every trekker has a value for every outcome, that the group column holds exactly two labels, and that the recorded values fall in physiologically sensible ranges. It performs no significance test of its own on the raw data and computes no p-value of its own.

Every significance verdict comes from the adjusted p-values loaded from the second CSV, matched to the outcomes by name and judged at the conventional 0.05 family level. The script prints its numbers and verdicts so a reader can follow them.

REPORT

report.md is short plain prose, a few hundred words. It includes a brief data description that lists every column of both files with its meaning and unit and states what a single row of each file represents; the design and the pre-declared outcome family in order; a plain statement that the family was tested and adjusted for multiplicity by the programme's central analysis stage and that this site's script only summarises the raw measurements and reads the adjusted values; the per-outcome descriptive numbers, the adjusted p-value and the conclusion for each outcome; and a closing statement of what the study found about prophylaxis. Numbers in the report must match what the script produces.
