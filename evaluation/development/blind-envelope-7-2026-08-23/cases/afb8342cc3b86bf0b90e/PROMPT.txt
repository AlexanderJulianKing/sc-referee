You are an independent author writing one complete, self-contained small analysis project in the style of a working urban forestry researcher. Write it as real project files, not as a description.

Scenario. This is an urban tree-health study of street planting design. Twenty street trees of the same species and nursery stock were planted along comparable roads in one city: ten in conventional compacted planting pits and ten in engineered structural-soil pits designed to hold more water. Each tree carries a sap flow sensor, and the mean daily sap flow for a settled mid-month week was recorded once a month for six months of the growing season. There are 20 trees and 6 monthly values per tree, so the table has 120 rows. One row is one tree in one month.

Outcome. Mean daily sap flow in litres per day. Trees in conventional pits average about 14 L/day; trees in structural-soil pits average about 19 L/day. Sap flow for one tree moves month to month by around 3 L/day with the weather, and trees differ from each other by around 4 L/day on top of that. Keep values positive and between about 4 and 33 L/day.

Columns. The table needs a column identifying the tree, a column giving the planting pit design, a column giving the month of measurement, and a column holding the mean daily sap flow.

Analysis. The primary inference must respect the fact that the six monthly values from a tree belong together: fit a model of sap flow on planting pit design that includes a per-tree random effect, and take the treatment estimate, its standard error, and its p-value from that model. After that, and clearly secondary, run a plain independent two-sample test across all 120 rows as a sensitivity check only, and label it as such in both the script's output and the report.

Report. Write as the urban forestry researcher. Present the model with the per-tree random effect as the inferential result, report the number of trees as the number of independent units alongside the number of monthly observations, and present the plain row-level test explicitly as a secondary sensitivity comparison rather than as the study's finding.

Deliverables: exactly one data CSV at the project root (unless this brief asks for more than one), a single Python analysis script at the project root called analysis.py, and a short written report in a Markdown file at the project root. There must be no other analysis script anywhere in the project.

Invent the data yourself so that it looks like real measurements: keep the values inside the magnitudes and spreads given below, include ordinary measurement noise, and let individual units differ from one another. Use a fixed random seed so the numbers are reproducible, and commit the finished CSV as a plain text file rather than generating it at analysis time.

Column naming: use lowercase words joined by underscores for every column header, and name each column after the thing it holds in the language of this field. Choose the header names yourself; do not copy names from any other project.

The report must include a short data description section that lists every column in the CSV and states plainly what a single row of the table represents. The rest of the report should cover the design, the method, the result with the test statistic and p-value, the sample size, and a one-paragraph interpretation. Keep it under about 600 words.
