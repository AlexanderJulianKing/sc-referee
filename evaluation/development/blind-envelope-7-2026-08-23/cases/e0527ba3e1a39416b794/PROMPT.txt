You are an independent author writing one complete, self-contained small analysis project in the style of a working fermentation scientist. Write it as real project files, not as a description.

Scenario. This is a food-fermentation study on sourdough starters. Twelve independent starter jars were built from scratch on the same bench: six were fed a wholemeal rye flour and six were fed a refined white wheat flour. Every jar was fed on the same daily schedule and held at the same temperature. The pH of each jar was measured once a day, at the same time each day, for six consecutive days of maturation. There are 12 jars and 6 daily readings per jar, so the table has 72 rows. One row is one jar on one day.

Outcome. Starter pH. Both flours start near pH 5.6 on day one and acidify over the week. Rye-fed jars settle near pH 3.60 by day six; wheat-fed jars settle near pH 3.90. Day-to-day measurement scatter within a jar is around 0.08 pH units, and jars differ from each other by around 0.12 pH units on top of that. Values should stay between about pH 3.3 and 5.8.

Columns. The table needs a column identifying the jar, a column giving the flour type the jar was fed, a column giving the maturation day, and a column holding the pH reading.

Analysis. Load the CSV and compare the two flours with a standard independent two-sample test of the difference in mean pH, pooling all six days and using every daily reading in the table as one observation in that test. Report the sample size as the total number of pH readings in each flour group. Also give the group means and standard deviations.

Report. Write as the fermentation scientist who ran the bench. State the number of readings per flour group as the sample size, give the test result, and conclude about which flour drives stronger acidification. Do not discuss, hedge about, or mention the repeated daily measurement of the same jars beyond the plain data description, and do not raise any concern about the statistical treatment.

Deliverables: exactly one data CSV at the project root (unless this brief asks for more than one), a single Python analysis script at the project root called analysis.py, and a short written report in a Markdown file at the project root. There must be no other analysis script anywhere in the project.

Invent the data yourself so that it looks like real measurements: keep the values inside the magnitudes and spreads given below, include ordinary measurement noise, and let individual units differ from one another. Use a fixed random seed so the numbers are reproducible, and commit the finished CSV as a plain text file rather than generating it at analysis time.

Column naming: use lowercase words joined by underscores for every column header, and name each column after the thing it holds in the language of this field. Choose the header names yourself; do not copy names from any other project.

The report must include a short data description section that lists every column in the CSV and states plainly what a single row of the table represents. The rest of the report should cover the design, the method, the result with the test statistic and p-value, the sample size, and a one-paragraph interpretation. Keep it under about 600 words.
