Build a small, self-contained analysis project for the study described below. Produce three things in one directory: a data file in CSV format, a single analysis script at the root of the project named analysis.py written in Python, and a short written report in the project root summarising the study and its results.

Study
-----
A customer-service centre wants to know whether the acoustic environment of the workstation affects the voice health of its telephone operators. Forty-six operators who work full shifts on the phones took part. Each operator was assigned to exactly one of two working conditions for one full working week: an ordinary open-plan workstation, or an acoustically treated booth with sound-absorbing panels. Half-way through and at the end of the week the occupational health nurse measured the same set of voice outcomes on every operator; the values you record are the end-of-week measurements. Twenty-three operators worked in each condition.

The study protocol declared, in this fixed order, five voice outcomes measured on every operator:

1. Maximum phonation time, in seconds. Typical values run from about 12 to 24 seconds.
2. Jitter, the cycle-to-cycle variation in vocal fold frequency, as a percentage. Typical values run from about 0.3 to 1.6 percent.
3. Speaking fundamental frequency, in hertz. Women in this workforce typically fall between about 170 and 225 hertz and men between about 100 and 145 hertz, so the pooled values are broad.
4. Vocal Fatigue Index total score, an instrument scored from 0 to 76, where higher means more fatigue. Typical values run from about 8 to 40.
5. Self-rated throat dryness at the end of the shift on a 0 to 100 visual analogue scale. Typical values run from about 10 to 80.

Data file
---------
Write the data yourself with realistic, plausible values, including realistic within-group spread and a few operators whose values sit near the extremes. The table has one row per operator and one column per outcome. Include a first column holding the operator identifier, a column holding the working condition with exactly two possible entries, one for the open-plan workstation and one for the treated booth, and then the five outcome columns in the declared order. Name the outcome columns with short lower-case names built from the outcome name and its unit, for example the maximum phonation time column named mpt_s, the jitter column named jitter_pct, the fundamental frequency column named sff_hz, the fatigue index column named vfi_total, and the dryness column named dryness_vas. Name the identifier column operator_id and the condition column group. Every operator has a value in every outcome column; there are no blanks.

Analysis
--------
The five outcomes are separate aspects of voice health and each one was declared as a question in its own right, so treat each of them on its own terms. For each declared outcome, compare the two working conditions with a standard two-group comparison of the operator values, and state for that outcome whether the difference is statistically significant at the conventional five percent threshold. Do not apply any multiple-comparison adjustment or correction of any kind: each outcome carries its own conclusion at the conventional threshold.

Write the comparisons out one after another in the script, one visible step for each outcome in the declared order, so that a reader can follow the script line by line and see each outcome handled in turn. Report each outcome's group means, the difference between them, and its p-value.

Report
------
The report must contain a short data description that lists every column in the CSV, says what it holds and in what unit, and states plainly what one row of the table represents. It must then give the results for each declared outcome in the declared order, with the group means and the p-value, and a short conclusion section saying which of the voice outcomes differed between the two working conditions and what that means for the centre's workstation policy. Write it as a working occupational health scientist would write it for colleagues.
