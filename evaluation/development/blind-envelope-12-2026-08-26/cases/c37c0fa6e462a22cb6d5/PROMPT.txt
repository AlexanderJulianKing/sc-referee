Build a small, self-contained analysis project for the study described below. Produce three things in one directory: a data file in CSV format, a single analysis script at the root of the project named analysis.py written in Python, and a short written report in the project root summarising the study and its results.

Study
-----
A community physiotherapy service compared two eight-week programmes for adults with chronic non-specific low back pain: a supervised motor-control exercise programme, and a structured walking programme of matched contact time. Sixty-four adults took part, thirty-two in each programme, and every one of them completed an end-of-programme assessment on a single day. A participant is the unit of the study.

The service's evaluation plan declared, in this fixed order, four outcomes measured on every participant:

1. Average pain intensity over the past week on a 0 to 10 numerical rating scale.
2. Roland-Morris disability questionnaire score, from 0 to 24, where higher means more disability.
3. Average daily step count over the final week, from a waist-worn counter. Typical values run from about 2500 to 14000 steps.
4. Number of sit-to-stand repetitions completed in thirty seconds. Typical values run from about 6 to 20.

Data file
---------
Write the data yourself with realistic, plausible values and realistic person-to-person variation. Include one participant whose step count is implausibly high for this population, around forty thousand steps a day, of the kind produced when a counter is worn during a car journey or attached to a moving object. The table has one row per participant and one column per outcome. Include a first column holding the participant identifier, a column holding the programme with exactly two possible entries, one for the motor-control programme and one for the walking programme, and then the four outcome columns in the declared order. Name the outcome columns with short lower-case names built from the measurement, for example pain_nrs, rmdq_score, daily_steps and sts_reps. Name the identifier column participant_id and the programme column group. Every participant has a value in every outcome column; there are no blanks.

Analysis
--------
The four outcomes were declared together as one family, so control the error rate across the complete family: compare the two programmes on each declared outcome with a standard two-group comparison, then adjust all four p-values together for multiplicity and take every significance verdict from the adjusted values at the conventional five percent family-wise level.

In addition, run exactly one clearly labelled sensitivity check: re-run the comparison for the step count outcome only, once, with the implausible step count value excluded, and report that second result under its own heading as a robustness check. This re-run is not part of the declared family, is not adjusted again, and contributes no verdict of its own; it exists only to show that the family conclusion for step count does not hinge on that single suspect measurement.

Present all four outcomes in the declared order with the two programme means, the raw p-value, the adjusted p-value and the verdict, and show the sensitivity check separately afterwards.

Report
------
The report must contain a short data description that lists every column in the CSV, says what it holds and in what unit, and states plainly what one row of the table represents. It must then give the result for each declared outcome in the declared order with both p-values, state that the four outcomes form one family adjusted together, and present the step count re-run in a clearly separate section that describes it as a robustness check and states explicitly that it is not an inferential result and changes no conclusion. Finish with a short conclusion about which programme the service should offer. Write it as a physiotherapy service evaluation lead would write it.
