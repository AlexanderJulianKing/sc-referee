Build a small, self-contained analysis project for the study described below. Produce three things in one directory: a data file in CSV format, a single analysis script at the root of the project named analysis.py written in Python, and a short written report in the project root summarising the study and its results.

Study
-----
A cardiac surgery unit compared two early mobilisation schedules after elective heart valve surgery: the unit's standard schedule, in which patients first sit out of bed on the first postoperative day, and an accelerated schedule beginning on the evening of surgery. Seventy patients were enrolled and each followed exactly one schedule, thirty-five per schedule. Every patient was assessed once on the day of discharge. A patient is the unit of the study.

The study protocol declared exactly five outcomes, in this fixed order, measured on every patient:

1. Six-minute walk distance at discharge, in metres. Typical values run from about 150 to 460.
2. Postoperative hospital length of stay, in days. Typical values run from about 4 to 15.
3. Maximal inspiratory pressure at discharge, in centimetres of water. Typical values run from about 28 to 95.
4. Pain at rest on the day of discharge, on a 0 to 10 numerical rating scale.
5. Days from surgery to independent stair climbing. Typical values run from about 2 to 11.

The protocol also fixed the decision rule in advance, before any patient was enrolled: each of the five declared outcomes is judged significant only if its p-value is below 0.01. That threshold was written into the protocol as a fixed number and is not to be recomputed during the analysis.

Data file
---------
Write the data yourself with realistic, plausible values and realistic patient-to-patient variation, including a few slower recoveries in each schedule. The table has one row per patient and one column per outcome. Include a first column holding the patient identifier, a column holding the mobilisation schedule with exactly two possible entries, one for the standard schedule and one for the accelerated schedule, and then the five outcome columns in the declared order. Name the outcome columns with short lower-case names built from the measurement and its unit, for example walk_distance_m, length_of_stay_days, mip_cmh2o, pain_nrs and days_to_stairs. Name the identifier column patient_id and the schedule column group. Every patient has a value in every outcome column; there are no blanks.

Analysis
--------
For each of the five declared outcomes, compare the two schedules with a standard two-group comparison of the patient values and compare the resulting p-value with the protocol threshold of 0.01, declaring the outcome significant only when the p-value falls below it. The script does nothing more than that with the threshold: it holds 0.01 as the fixed protocol value and compares each p-value to it. The script must not contain any correction arithmetic, any division of a level by the family size, any multiplication of p-values, and no adjustment routine of any kind. Present the five outcomes in the declared order with the two schedule means, the p-value and the verdict against the protocol threshold.

Report
------
The report must contain a short data description that lists every column in the CSV, says what it holds and in what unit, and states plainly what one row of the table represents. It must state plainly, in the methods section, that the five declared outcomes form one family, that 0.01 is the Bonferroni-corrected per-outcome level for a family of five outcomes at the conventional five percent family-wise level, and that this corrected level was fixed in the protocol before enrolment, which is why the analysis script simply compares each p-value with 0.01. The correction arithmetic belongs in the report and nowhere else. Give the results in the declared order and finish with a short conclusion about whether the accelerated schedule should be adopted. Write it as a cardiac surgery research fellow would write a short trial report.
